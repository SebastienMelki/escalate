## Unsatisfied Requirements Detail

### MDIA-01: Voice Note Transcription (UNSATISFIED)

**Requirement:** Voice note interpretation -- download audio from Slack thread, send to Claude API for transcription, normalize to text response

**What works:** The Slack adapter correctly downloads audio, transcribes via Whisper API, and resolves the escalation store record. Phase 6 verification confirmed this.

**What breaks:** `store.resolve()` stores `{type: 'voice', text: '...'}` in the response JSON. When hook scripts poll `GET /escalations/:id` and parse the response, `output-helpers.ts` checks `response.type === 'action'` (for PermissionRequest/PreToolUse) and `response.type === 'text'` (for Stop). Neither matches `'voice'`, resulting in a **DENY** decision regardless of the transcribed content.

**Root cause:** `scripts/lib/output-helpers.ts` was written in Phase 4 before Phase 6 added the `'voice'` response type. No cross-phase update was made.

**Fix:** Add `type === 'voice'` handling in output-helpers, treating transcribed voice text equivalently to thread reply text. Alternatively, normalize store JSON to `type:'text'` for voice notes since the content is transcribed text.

### MDIA-02: Emoji Reaction Mapping (UNSATISFIED)

**Requirement:** Emoji reaction responses -- configurable emoji-to-decision mapping (e.g., checkmark = approve, X = deny)

**What works:** The Slack adapter correctly maps emoji reactions to decisions (e.g., thumbsup -> approve) and resolves the escalation store record with `{type: 'reaction', actionId: 'approve', emoji: 'thumbsup'}`.

**What breaks:** `output-helpers.ts` checks `response.type === 'action'` for PermissionRequest/PreToolUse. `'reaction' !== 'action'` -> FALSE -> default **DENY**, even when `actionId` is `'approve'`.

**Root cause:** Same as MDIA-01 -- output-helpers predates the `'reaction'` response type.

**Fix:** Add `type === 'reaction'` handling alongside `type === 'action'` in output-helpers, since both carry a usable `actionId` field.

### IPC-03: Configurable Timeout (PARTIAL)

**Requirement:** Hook scripts poll SQLite for user response with configurable timeout (default 10 minutes for PermissionRequest)

**What works:** Config schema defines `timeouts` per event type. HTTP bridge accepts `timeout_seconds` in POST body. Store uses it for `timeout_at`.

**What's partial:** Hook scripts hardcode `timeout_seconds` (600/300/600/60) instead of reading from config. Defaults match so behavior is correct out of the box. Changing config has no practical effect.

**Severity:** Low. Correct at defaults.
