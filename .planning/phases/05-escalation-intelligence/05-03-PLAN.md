Modify `src/server/http-bridge.ts`:

1. Add imports: `evaluateRules`, `extractFilePaths` from `../intelligence/rules.js`, `isQuietHours`, `isCriticalEvent` from `../intelligence/quiet-hours.js`, `appendAuditEntry` from `../intelligence/audit.js`, `loadConfig` from `../config/index.js`.

2. Add `auditLogPath` to `HttpBridgeOptions`: `auditLogPath?: string`. The server entrypoint will set this to `$CLAUDE_PROJECT_DIR/.claude/escalate-audit.jsonl`.

3. Restructure `POST /escalations` handler BEFORE the existing Slack dispatch:

   a. Parse the hook input: `const hookInput = JSON.parse(request_json) as Record<string, unknown>`
   b. Re-read config on every request: `const configResult = loadConfig()`. If config load fails, fall through to existing escalation behavior (do not block on config error).
   c. Extract evaluation inputs: `const toolName = hookInput['tool_name'] as string | undefined`, `const filePaths = extractFilePaths(toolName, (hookInput['tool_input'] ?? {}) as Record<string, unknown>)`
   d. Get escalation policy for event type: look up `config.escalationPolicies[eventType]` using bracket notation (noPropertyAccessFromIndexSignature). Default to `'always'` if not found.
   e. Evaluate auto-approval rules: `const ruleResult = evaluateRules({ eventType: event_type, toolName, filePaths }, config.autoApprovalRules, policy)`
   f. Check quiet hours: if `ruleResult.decision === 'escalate'` AND `isQuietHours(config.quietHours)` AND `!isCriticalEvent(event_type, config.quietHours.criticalEvents)`, set decision to `'quiet_hours_suppress'`.
   g. Audit log: call `appendAuditEntry(options.auditLogPath ?? defaultAuditPath, { timestamp: new Date().toISOString(), eventType: event_type, toolName, filePaths, decision, reason, matchedRule: ruleResult.matchedRule?.description })`. Wrap in try/catch -- audit failure MUST NOT block escalation.
   h. If decision is `auto_approve` or `quiet_hours_suppress`: create SQLite record via `store.create()`, immediately resolve it with `store.resolve(record.id, JSON.stringify({ type: 'action', actionId: 'approve' }))`, return `{ escalation_id: record.id, status: 'resolved' }` with 201. Skip Slack dispatch entirely.
   i. If decision is `escalate`: proceed with existing flow (create record, fire-and-forget Slack message). Also append to audit log with decision='escalated'.

4. Add `POST /summary` endpoint:
   - Import `buildSessionSummary`, `buildSummaryBlocks` from `../intelligence/summary.js`.
   - When `POST /summary` received: read audit log path from options, call `buildSessionSummary(auditLogPath)`, call `buildSummaryBlocks(summary)`.
   - To send the summary, use type-narrowing on the adapter (NOT `sendFollowUp`, which accepts `(escalationId, string)` and posts to an escalation thread -- a session summary is a top-level message, not a thread reply):
     ```typescript
     if (options.adapter && options.adapter.isConnected() && 'sendSummary' in options.adapter) {
       await (options.adapter as { sendSummary: (blocks: KnownBlock[]) => Promise<void> }).sendSummary(blocks);
     }
     ```
     This calls `SlackAdapter.sendSummary()` (added below) without changing the `MessagingAdapter` interface.
   - If no adapter or adapter lacks `sendSummary`: return 200 with `{ status: 'no_adapter' }`.
   - Return 200 with `{ status: 'sent', summary }`.

   **SlackAdapter.sendSummary() -- add to `src/slack/adapter.ts`:**
   Add a `sendSummary(blocks: KnownBlock[]): Promise<void>` method to `SlackAdapter`. This method is NOT part of the `MessagingAdapter` interface -- it is Slack-specific. Implementation:
   ```typescript
   async sendSummary(blocks: KnownBlock[]): Promise<void> {
     await this.app.client.chat.postMessage({
       channel: this.channelId,
       blocks,
       text: 'Session Summary',  // fallback for notifications
     });
   }
   ```
   Import `KnownBlock` from `@slack/bolt` at the top of the file (it re-exports from `@slack/types`).
   This posts a top-level message to the configured channel, not a threaded reply.

5. For quiet hours suppression, the auto-resolved response should use the event type's configured `fallbackAction` instead of always approving. For PreToolUse with fallback='deny', the response should be `{ type: 'action', actionId: 'deny' }`. For Stop with fallback='ask-again', use `{ type: 'action', actionId: 'allow' }` (since user is not available during quiet hours, ask-again maps to allow per research recommendation).

Modify `src/server/index.ts`:
- Pass `auditLogPath` to `HttpBridgeOptions`: `join(projectDir, '.claude', 'escalate-audit.jsonl')`.

IMPORTANT: Do NOT use console.log() anywhere -- only console.error() for debug output (MCP stdio constraint).
