    **In bridge-client.ts:**
    1. Add imports at the top: `resolve` from `node:path`, `loadConfig` from `../../src/config/loader.js`, `DEFAULT_TIMEOUTS` from `../../src/config/defaults.js`.
    2. Define `type TimeoutEventType = keyof typeof DEFAULT_TIMEOUTS;` for type safety.
    3. Add the `readTimeoutMs` function:
       - Resolve config path using `CLAUDE_PROJECT_DIR ?? process.cwd()` pattern (same as `readPort()`)
       - Call `loadConfig(configPath)` and check `result.success`
       - On success: return `result.data.timeouts[eventType]`
       - On failure: return `DEFAULT_TIMEOUTS[eventType]`
    4. Export `readTimeoutMs` (add to existing exports).

    **In test/bridge-client.test.ts:**
    Add a `describe('readTimeoutMs', ...)` block with tests:
    1. "returns default timeout when config file is missing" -- stub `CLAUDE_PROJECT_DIR` to `/nonexistent/path`, call `readTimeoutMs('permissionRequest')`, assert equals `DEFAULT_TIMEOUTS.permissionRequest` (600_000).
    2. "returns custom timeout from config file" -- create temp dir with `escalate.config.json` containing `{ "slack": { "channelId": "C0123456789" }, "timeouts": { "permissionRequest": 120_000 } }`, stub `CLAUDE_PROJECT_DIR` to temp dir, assert `readTimeoutMs('permissionRequest')` returns 120_000. Clean up temp dir after.
    3. "returns default for event type not explicitly in config timeouts" -- create temp dir with `escalate.config.json` containing `{ "slack": { "channelId": "C0123456789" } }` (no timeouts section), stub `CLAUDE_PROJECT_DIR`, assert `readTimeoutMs('preToolUse')` returns `DEFAULT_TIMEOUTS.preToolUse` (300_000). The Zod schema applies defaults when the timeouts section is absent.

    Import `readTimeoutMs` from `../scripts/lib/bridge-client.js` and `DEFAULT_TIMEOUTS` from `../src/config/defaults.js`.

    **IMPORTANT:** Config values are already in milliseconds (DEFAULT_TIMEOUTS uses 600_000, 300_000, etc.). The function returns milliseconds. Callers convert to seconds for the bridge with `Math.ceil(timeoutMs / 1000)`.
