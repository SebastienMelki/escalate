<objective>
Create the shared bridge client library that all hook scripts import, and wire the HTTP bridge to trigger Slack messages when escalations are created.

Purpose: This closes the critical integration gap identified in research — currently POST /escalations only writes to SQLite but does not send a Slack message. Without this wiring, the escalation loop is broken. The bridge client provides the reusable HTTP communication layer that keeps all four hook scripts thin (<50 lines).

Output: `scripts/lib/bridge-client.ts` with readPort/createEscalation/pollForResponse, updated `http-bridge.ts` that accepts an optional SlackAdapter and calls sendEscalation on POST, updated `server/index.ts` that passes the adapter to the bridge.
</objective>

2. In the `POST /escalations` handler, AFTER creating the SQLite record via `store.create()`, if `adapter` is defined and `adapter.isConnected()`, trigger a Slack message:
   ```typescript
   if (adapter?.isConnected()) {
     // Parse the hook event JSON to build an EscalationRequest
     const hookInput = JSON.parse(request_json) as Record<string, unknown>;
     const escalationRequest: EscalationRequest = {
       title: `${event_type}: ${String(hookInput.tool_name ?? 'Unknown')}`,
       question: buildQuestionFromEvent(event_type, hookInput),
       urgency: event_type === 'PostToolUseFailure' ? 'warning' : 'critical',
       context: {
         eventType: event_type,
         toolName: hookInput.tool_name as string | undefined,
       },
       suggestedActions: buildActionsForEvent(event_type),
       allowFreeformResponse: true,
     };
     // Fire-and-forget — don't block the HTTP response
     void adapter.sendEscalation(escalationRequest).catch((err: unknown) => {
       console.error('[escalate] Failed to send Slack escalation:', err);
     });
   }
   ```

3. Add two helper functions at the top of the file (not exported):
   - `buildQuestionFromEvent(eventType: string, input: Record<string, unknown>): string` — returns a human-readable question based on event type:
     - PermissionRequest: `"Allow ${tool_name}? ${JSON.stringify(tool_input).slice(0, 200)}"`
     - PreToolUse: `"Allow ${tool_name} before execution? ${JSON.stringify(tool_input).slice(0, 200)}"`
     - Stop: `"Claude wants to stop. ${last_assistant_message?.slice(0, 200) ?? 'No context.'}"`
     - PostToolUseFailure: `"Tool failure: ${tool_name} — ${error?.slice(0, 200) ?? 'Unknown error'}"`
     - Default: `"Event: ${eventType}"`
   - `buildActionsForEvent(eventType: string): SuggestedAction[]` — returns appropriate buttons:
     - PermissionRequest: `[{id: 'approve', label: 'Approve', style: 'primary'}, {id: 'deny', label: 'Deny', style: 'danger'}]`
     - PreToolUse: same as PermissionRequest
     - Stop: `[{id: 'stop', label: 'Stop', style: 'danger'}, {id: 'continue', label: 'Continue', style: 'primary'}]`
     - PostToolUseFailure: `[{id: 'acknowledge', label: 'Acknowledged'}]` (informational only)
     - Default: `[{id: 'approve', label: 'Approve', style: 'primary'}, {id: 'deny', label: 'Deny', style: 'danger'}]`

4. Import EscalationRequest and SuggestedAction from `'../types/escalation.js'`.

**Modify `src/server/index.ts`:**

5. Pass `slackAdapter` to `createHttpBridge`:
   - Move the `createHttpBridge` call AFTER Slack adapter initialization (currently it's before)
   - OR: Create bridge first, then set adapter later. Since createHttpBridge returns a Server, the simplest approach is to reorder: create store, create MCP server, start Slack adapter, THEN create HTTP bridge with slackAdapter.
   - However, the HTTP server needs to start before we can write the port file. And Slack adapter is optional.
   - Best approach: Keep current order but change createHttpBridge to accept a setter. Actually simplest: just pass the `slackAdapter` variable (which may be undefined initially) by closing over it. But that won't work since it's reassigned.
   - Cleanest approach: Create the bridge with `undefined` adapter, then after Slack is initialized, set the adapter on the bridge. Add a `setAdapter(adapter: MessagingAdapter)` to the bridge module via a closure.

   Actually, looking at the code more carefully: `createHttpBridge` creates a closure over the request handler. The simplest pattern is to use a mutable reference object:

   In `http-bridge.ts`, change the signature to:
   ```typescript
   export interface HttpBridgeOptions {
     store: EscalationStore;
     adapter?: MessagingAdapter;
   }
   export function createHttpBridge(options: HttpBridgeOptions): Server
   ```

   Then in `server/index.ts`, create a shared options object:
   ```typescript
   const bridgeOptions: HttpBridgeOptions = { store };
   httpServer = createHttpBridge(bridgeOptions);
   // ... later after Slack init:
   bridgeOptions.adapter = slackAdapter;
   ```

   This works because the request handler closes over `bridgeOptions` and reads `.adapter` at request time, not at creation time.

CRITICAL: Do NOT use console.log() — only console.error() for logging. MCP stdio must remain clean.
