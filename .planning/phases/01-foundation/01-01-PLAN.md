  <action>
    Create the core type definitions that all downstream phases import from.

    1. Create `src/errors/result.ts`:
       - Define `Result<T, E>` as a discriminated union: `{ readonly success: true; readonly data: T } | { readonly success: false; readonly error: E }`
       - Export constructor functions: `ok<T>(data: T): Result<T, never>` and `err<E>(error: E): Result<never, E>`
       - Export type guards: `isOk<T, E>(result): result is { success: true; data: T }` and `isErr<T, E>(result): result is { success: false; error: E }`
       - Export utility: `unwrapOr<T, E>(result, fallback: T): T`
       - All properties must be `readonly`

    2. Create `src/types/escalation.ts`:
       - `UrgencyLevel = 'info' | 'warning' | 'critical'` (3 tiers per locked decision)
       - `ResponseType = 'action' | 'text' | 'timeout'`
       - `SuggestedAction` interface: `{ readonly id: string; readonly label: string; readonly style?: 'primary' | 'danger' | 'default' }` -- Note: with exactOptionalPropertyTypes, `style` should be `style?: 'primary' | 'danger' | 'default' | undefined` only if setting it to undefined explicitly is valid. Since style is purely optional (omit if not needed), use `style?: 'primary' | 'danger' | 'default'` without `| undefined`.
       - `EscalationContext` interface: `{ readonly eventType: string; readonly toolName?: string; readonly filePaths?: readonly string[]; readonly taskContext?: string }`
       - `EscalationRequest` interface: `{ readonly title: string; readonly question: string; readonly urgency: UrgencyLevel; readonly context: EscalationContext; readonly suggestedActions: readonly SuggestedAction[]; readonly allowFreeformResponse: boolean }`
       - `UserResponse` interface: `{ readonly type: ResponseType; readonly actionId?: string; readonly text?: string; readonly respondedAt: Date }`
       - `EscalationTimeout` interface: `{ readonly type: 'timeout'; readonly timeoutMs: number; readonly fallbackAction: 'block' }` (always block when unreachable -- locked decision)
       - Export all types

    3. Create `src/types/adapter.ts`:
       - Import types from `./escalation.js` (use `.js` extension for ESM compatibility)
       - Define `MessagingAdapter` interface with exactly 4 methods:
         - `sendEscalation(request: EscalationRequest): Promise<string>` -- returns escalation ID
         - `waitForResponse(escalationId: string, timeoutMs: number): Promise<UserResponse>` -- returns response or times out
         - `sendFollowUp(escalationId: string, message: string): Promise<void>` -- threaded reply
         - `isConnected(): boolean` -- connection status check
       - Export `MessagingAdapter`

    4. Create `src/types/index.ts`:
       - Barrel re-export from `./escalation.js` and `./adapter.js`
       - Use `export type` for type-only re-exports (required by verbatimModuleSyntax)

    5. Create `src/index.ts` (tsup entry point):
       - Re-export from `./types/index.js` and `./errors/result.js`
       - Use `export type` and `export` appropriately
       - This is the minimal entry point for tsup to produce dist/ output

    CRITICAL: All imports between .ts files must use `.js` extensions (ESM requirement). TypeScript resolves `.js` imports to `.ts` files during compilation.

    CRITICAL: With `exactOptionalPropertyTypes: true`, be careful with optional properties. `foo?: string` means the property can be absent but CANNOT be explicitly set to `undefined`. Only add `| undefined` if explicitly setting to undefined is a valid use case.
