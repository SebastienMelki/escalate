  <behavior>
    Config schema validation (schema.test.ts):
    - Valid minimal config (just slack.channelId) -> parses successfully with defaults applied
    - Valid full config (all fields explicit) -> parses successfully with provided values
    - Missing slack.channelId -> validation error (required field)
    - Empty channelId string -> validation error (min length)
    - Invalid urgency level (e.g., "high") -> validation error
    - Invalid escalation policy (e.g., "maybe") -> validation error
    - Invalid timeout (0 or negative) -> validation error
    - Extra unknown fields -> stripped (Zod default behavior) or allowed (verify Zod 4 behavior)
    - Default timeouts: permissionRequest=600000, preToolUse=300000, stop=600000, postToolUseFailure=60000
    - Default escalation policies: permissionRequest=always, preToolUse=conditional, stop=always, postToolUseFailure=always

    Config loading (loader.test.ts):
    - loadConfig with valid file path -> Result with success=true, data is validated config
    - loadConfig with nonexistent file -> Result with success=false, error.code='FILE_NOT_FOUND'
    - loadConfig with malformed JSON file -> Result with success=false, error.code='INVALID_JSON'
    - loadConfig with invalid schema data -> Result with success=false, error.code='VALIDATION_FAILED'
    - loadConfig with no argument -> uses default path (process.cwd() + 'escalate.config.json')
    - loadSecrets with both env vars set -> Result with success=true
    - loadSecrets with missing ESCALATE_SLACK_BOT_TOKEN -> Result with success=false, error.code='MISSING_ENV_VAR'
    - loadSecrets with missing ESCALATE_SLACK_APP_TOKEN -> Result with success=false, error.code='MISSING_ENV_VAR'
  </behavior>
