<objective>
Add handling for `type:'reaction'` and `type:'voice'` response types in `output-helpers.ts` so emoji reactions and voice note approvals complete the full hook output path.

Purpose: The Slack adapter correctly stores `type:'reaction'` and `type:'voice'` responses in SQLite, but when hook scripts poll `GET /escalations/:id` and pass the result through output-helpers, only `type:'action'` and `type:'text'` are recognized. This causes all emoji and voice note responses to fall through to the default DENY path, breaking 2 E2E flows.

Output: Updated output-helpers.ts with shared helper functions handling all 5 ResponseType variants, plus comprehensive test coverage.
</objective>

<task type="auto">
  <name>Task 1: Add shared helpers and reaction/voice handling to output-helpers.ts</name>
  <files>scripts/lib/output-helpers.ts</files>
  <action>
Add three shared helper functions and update all output builder functions in `scripts/lib/output-helpers.ts`:

1. **Add `isApprovalDecision(response: ParsedResponse): boolean`** — Returns true when `(type === 'action' || type === 'reaction') && actionId === 'approve'`. Both button clicks and emoji reactions carry `actionId`.

2. **Add `isContinueDecision(response: ParsedResponse): boolean`** — Returns true when `(type === 'action' || type === 'reaction') && actionId === 'continue'`. Used by Stop hook to block stop.

3. **Add `extractText(response: ParsedResponse): string | null`** — Returns `response.text` as string when `(type === 'text' || type === 'voice') && typeof response.text === 'string'`. Returns null otherwise. Voice notes carry transcribed text like thread replies.

4. **Update `buildPermissionRequestOutput`** — Replace the inline `response.type === 'action' && response.actionId === 'approve'` check with `isApprovalDecision(response)`. Voice notes without actionId correctly fall through to DENY (conservative default).

5. **Update `buildPreToolUseOutput`** — Same change as PermissionRequest: replace inline check with `isApprovalDecision(response)`.

6. **Update `buildStopOutput`** — Replace inline `response.type === 'action' && response.actionId === 'continue'` with `isContinueDecision(response)`. Replace inline `response.type === 'text' && typeof response.text === 'string'` with `const text = extractText(response); if (text) { ... }`. This gives voice notes the same behavior as thread replies on Stop hooks (block stop with transcribed text as reason).

**Important constraints:**
- Keep `ParsedResponse` interface unchanged (loose `type?: unknown` is intentional for untrusted JSON)
- Keep `parseResponse` unchanged
- Keep `buildPostToolFailureOutput` unchanged (no response to parse)
- Do NOT add voice-text intent parsing or keyword matching for approval detection — voice text is context, not a decision
- All three helpers are module-private (not exported), only used within output-helpers.ts

Existing `type:'action'` and `type:'text'` behavior is unchanged.</done>
