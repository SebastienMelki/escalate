**TDD: RED-GREEN-REFACTOR cycle for the escalation state store.**

**RED phase — write failing tests first:**

Create `test/state/store.test.ts` with tests covering:

1. **Schema initialization**: `initializeDatabase(db)` creates the `escalations` table
2. **Create escalation**: `store.create({ eventType, requestJson, fallbackAction, timeoutSeconds })` inserts a row with status='pending', auto-generated UUID id, and computed `timeout_at`
3. **Get by ID**: `store.getById(id)` returns the escalation record or undefined
4. **Resolve escalation**: `store.resolve(id, responseJson)` sets status='resolved', response_json, resolved_at; returns true. Resolving already-resolved or non-existent returns false.
5. **Check timeout**: `store.checkTimeout(id)` returns the fallback action if `timeout_at` is past and status is still 'pending', or null if not timed out
6. **Get pending escalations**: `store.getPending()` returns all pending escalations ordered by created_at
7. **Fallback action values**: tests for 'allow', 'deny', and 'ask-again' fallback actions

Use `better-sqlite3` in-memory database (`:memory:`) for all tests — no file I/O, fast isolation.

Import `Database` from `better-sqlite3` directly in tests.

**GREEN phase — implement minimally:**

`src/state/types.ts`:
- `FallbackAction` = `'allow' | 'deny' | 'ask-again'`
- `EscalationStatus` = `'pending' | 'resolved' | 'timed_out'`
- `EscalationRecord` interface with fields: `id: string`, `status: EscalationStatus`, `eventType: string`, `requestJson: string`, `responseJson: string | null`, `fallbackAction: FallbackAction`, `createdAt: string`, `resolvedAt: string | null`, `timeoutAt: string`
- `CreateEscalationParams` interface with: `eventType: string`, `requestJson: string`, `fallbackAction: FallbackAction`, `timeoutSeconds: number`

`src/state/schema.ts`:
- `initializeDatabase(db: DatabaseType)` — enables WAL mode, busy_timeout=5000, foreign_keys=ON, creates `escalations` table with STRICT mode
- Table columns: `id TEXT PRIMARY KEY, status TEXT NOT NULL DEFAULT 'pending', event_type TEXT NOT NULL, request_json TEXT NOT NULL, response_json TEXT, fallback_action TEXT NOT NULL DEFAULT 'deny', created_at TEXT NOT NULL DEFAULT (datetime('now')), resolved_at TEXT, timeout_at TEXT NOT NULL`

`src/state/store.ts`:
- `EscalationStore` class that takes a `better-sqlite3` `Database` instance in constructor
- Constructor calls `initializeDatabase(db)` then prepares all statements
- Methods: `create(params: CreateEscalationParams): EscalationRecord`, `getById(id: string): EscalationRecord | undefined`, `resolve(id: string, responseJson: string): boolean`, `checkTimeout(id: string): FallbackAction | null`, `getPending(): EscalationRecord[]`
- `create` generates a UUID via `crypto.randomUUID()`, computes `timeout_at` as `datetime('now', '+N seconds')`, returns the inserted record
- `checkTimeout` checks if `timeout_at < datetime('now')` AND status is 'pending'. If so, updates status to 'timed_out' and returns the fallback_action. Otherwise returns null.

`src/state/index.ts`:
- Barrel re-export all types from `types.ts`, `initializeDatabase` from `schema.ts`, `EscalationStore` from `store.ts`
